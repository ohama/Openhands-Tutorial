## Overview

Extend the v1.4 Planning Comparison with a **third arm, Arm C** — an expert plan produced by the **GSD multi-agent pipeline** (gsd-phase-researcher → gsd-planner → gsd-plan-checker) rather than hand-authored (Arm A) or self-planned (Arm B). Because the GSD pipeline naturally embeds full reference code, two variants were captured to separate *planning* from *answer-handover*:

- **Arm C-mech** — the GSD plan with all code/answers/API-DSL syntax **stripped**, leaving only failure-mode guidance as prose (respects the unaided discipline; comparable to Arm A but pitfall-aware).
- **Arm C-orig** — the GSD plan handed over **AS-IS, with the reference code included** (a diagnostic, not a capability measure).

Captured on the local 35B at n=1 per cell (NOT counterbalanced vs the v1.4 n=3 runs; timing not comparable), published into 부록 D §6. This was an exploratory post-v1.4 follow-up — no separate formal REQUIREMENTS/MILESTONE-AUDIT documents (disclosed); correctness held via the same honesty discipline (control-block symmetry PASS, source=agent honesty gates, fixed canonical detector, ground-truth host verification).

## Result

Across the full 4-condition matrix (Arm A / Arm B / Arm C-mech / Arm C-orig):

| Example | Arm A (n=3) | Arm B (n=3) | Arm C-mech, no code (n=1) | Arm C-orig, with code (n=1) |
|---------|-------------|-------------|---------------------------|------------------------------|
| F# (OOD) | 1/3 | 0/3 | **FAIL** | **PASS** |
| Scala (in-dist) | 3/3 | 2/3 + PARTIAL | PASS | PASS |
| Rust (in-dist) | 3/3 | 3/3 | PASS | n/a (harness bug) |

**Sharpened thesis — "distribution, not size":** for in-distribution work (Rust, Scala) every condition succeeds, even code-free self-planning. For the OOD DSL (F#) the dividing line is **code, not plan quality** — no amount of planning (even GSD-grade, failure-mode-aware, code-free) closes the gap; only handing over the literal `.fsl`/`.fsy` source does, and that is transcription rather than capability. The bottleneck is DSL-syntax authorship.
